Performance e Tempo de Resposta

NFR-001 CRÍTICA
Tempo de Carregamento Inicial
A aplicação deve carregar completamente e estar pronta para interação do usuário dentro de limites de tempo específicos, garantindo uma experiência fluida mesmo em conexões mais lentas.
Métrica de Performance
< 3 segundos Tempo máximo para First Contentful Paint (FCP)
Time to Interactive (TTI)
< 5 segundos Tempo até a página estar totalmente interativa
Condições de Teste
  • Conexão 4G simulada (3 Mbps down, 750 Kbps up)
  • Dispositivo médio (CPU 4x slowdown no DevTools)
  • Cache limpo (primeira visita)
  • Medição usando Lighthouse CI
NFR-002 CRÍTICA
Tempo de Resposta de APIs
Todas as requisições à API devem responder dentro de tempos aceitáveis para não comprometer a experiência do usuário durante operações críticas.
Tipo de Operação Tempo Máximo (p95) Tempo Ideal (p50)
Leitura simples (GET) 500ms 200ms
Criação/Atualização (POST/PUT) 1.000ms 500ms
Listagem paginada 800ms 400ms
Upload de pacote ZIP 5.000ms 3.000ms
Validação e processamento 2.000ms 1.000ms
⚠️ Ações em Caso de Timeout
  • Exibir mensagem clara: "Operação está demorando mais que o esperado"
  • Oferecer opção de cancelamento
  • Implementar retry automático (máximo 3 tentativas com backoff exponencial)
  • Logar timeout no Sentry para análise
NFR-003 ALTA
Otimização de Renderização
A interface deve permanecer responsiva durante operações pesadas, evitando bloqueios da thread principal.
Frame Rate Mínimo
> 30 FPS Durante scroll, animações e transições
✅ Estratégias de Otimização
  • Virtualização de listas longas (react-window ou similar)
  • Lazy loading de componentes pesados
  • Debounce em campos de busca (300ms)
  • Web Workers para processamento pesado
  • Paginação server-side para datasets grandes

Escalabilidade e Capacidade

NFR-004 CRÍTICA
Usuários Simultâneos
O sistema deve suportar múltiplos usuários operando simultaneamente sem degradação significativa de performance.
Fase do Projeto Usuários Simultâneos Transações/Segundo
MVP (Mês 1-3) 10-20 50 TPS
Lançamento (Mês 6) 50-100 200 TPS
Ano 1 (Mês 12) 200-500 1.000 TPS
Ano 2+ (Expansão) 1.000+ 5.000+ TPS
Testes de Carga Obrigatórios
  • Testes de stress antes de cada release major
  • Ferramenta: k6 ou Apache JMeter
  • Cenários: pico de 2x a carga esperada
  • Monitoramento de CPU, memória e latência de DB
NFR-005 ALTA
Volume de Dados
O sistema deve manter performance aceitável mesmo com crescimento significativo no volume de dados armazenados.
Capacidade de Ordens de Serviço
100.000+ O.S. no banco sem degradação de queries
Pacotes Fotográficos
50.000+ Pacotes armazenados com metadata indexada
✅ Estratégias de Escalabilidade
  • Índices otimizados em colunas de busca frequente
  • Arquivamento automático de O.S. > 2 anos
  • Particionamento de tabelas por ano/contrato
  • CDN para assets estáticos (Cloudflare)
  • Cache de queries frequentes (Redis/Supabase Edge Functions)

Segurança e Proteção de Dados

NFR-006 CRÍTICA
Autenticação e Autorização
Todo acesso ao sistema deve ser autenticado e autorizado conforme perfis de usuário, seguindo o princípio do menor privilégio.
Requisitos de Autenticação
  • JWT com expiração de 7 dias (refresh automático)
  • Logout em 30 dias de inatividade
  • Autenticação via Supabase Auth
  • Suporte a MFA (Multi-Factor Authentication) - Fase 2
  • Rate limiting de login: 5 tentativas/5 minutos
Perfil Permissões Restrições
Técnico Visualizar O.S. atribuídas, Upload de pacotes Sem acesso a gestão ou validação
Gerente CRUD completo de O.S., Atribuição, Validação Sem acesso a configurações de sistema
Admin Acesso total, gestão de usuários e contratos Logs de auditoria obrigatórios
Diretor Somente leitura de dashboards e métricas Sem acesso a operações
NFR-007 CRÍTICA
Proteção de Dados (LGPD)
O sistema deve estar em conformidade total com a Lei Geral de Proteção de Dados (LGPD), garantindo privacidade e controle dos dados pessoais.
✅ Medidas de Conformidade LGPD
  • Criptografia de dados sensíveis em repouso (AES-256)
  • Comunicação exclusivamente via HTTPS (TLS 1.3)
  • Opt-in explícito para coleta de dados analíticos
  • Direito ao esquecimento: exclusão completa em até 30 dias
  • Exportação de dados pessoais em formato JSON/CSV
  • Anonimização de dados em logs e analytics
  • DPO designado (Thiago Nascimento Barbosa)
  • Consentimento granular por finalidade de uso
Retenção de Dados
Conta Ativa + 90 dias Dados mantidos após cancelamento para compliance fiscal
NFR-008 ALTA
Proteção Contra Vulnerabilidades
O sistema deve implementar proteções contra as vulnerabilidades mais comuns definidas pelo OWASP Top 10.
Vulnerabilidade OWASP Proteção Implementada
Injection (SQL, XSS) Prepared statements, sanitização de inputs, CSP headers
Broken Authentication JWT com expiração, rate limiting, MFA (Fase 2)
Sensitive Data Exposure HTTPS obrigatório, criptografia em repouso
XML External Entities (XXE) Validação de uploads, rejeição de XML malformado
Broken Access Control RLS (Row Level Security) no Supabase
Security Misconfiguration Ambientes separados, secrets em variáveis de ambiente
CSRF CSRF tokens, SameSite cookies
⚠️ Auditorias de Segurança
  • Scan automatizado de dependências (npm audit, Snyk)
  • Análise estática de código (SonarQube)
  • Penetration testing trimestral (Fase Pós-MVP)
  • Revisão de logs de acesso suspeito

Disponibilidade e Confiabilidade

NFR-009 CRÍTICA
Uptime do Sistema
O sistema deve manter alta disponibilidade para não interromper operações críticas dos usuários.
Meta de Disponibilidade
99.5% Equivalente a ~3.6 horas de downtime/mês
Janelas de Manutenção
Domingos 02h-05h BRT Manutenção programada com aviso prévio de 48h
Monitoramento de Uptime
  • Health checks a cada 1 minuto (UptimeRobot ou Pingdom)
  • Alertas via Slack/Email em caso de downtime > 2 minutos
  • Status page pública (status.maffeng.com)
  • Histórico de incidentes transparente
NFR-010 ALTA
Recuperação de Desastres
O sistema deve possuir estratégias robustas de backup e recuperação para minimizar perda de dados em caso de falhas catastróficas.
Métrica Objetivo Estratégia
RTO (Recovery Time) < 4 horas Infraestrutura em cloud com failover automático
RPO (Recovery Point) < 24 horas Backups diários do Supabase
Retenção de Backups 30 dias Backups incrementais + snapshots semanais completos
✅ Plano de Backup
  • Backup automático diário do PostgreSQL (Supabase)
  • Backup semanal completo armazenado em região separada
  • Backup de configurações e secrets em vault seguro
  • Testes de restore mensais para validar integridade
  • Documentação atualizada de procedimentos de recuperação
NFR-011 MÉDIA
Tolerância a Falhas
O sistema deve continuar operando parcialmente mesmo quando componentes individuais falham.
Estratégias de Resiliência
  • Graceful degradation: funcionalidades não-críticas podem falhar sem quebrar o sistema
  • Circuit breakers para APIs externas (Auto Relatórios, TM Levantamentos)
  • Retry automático com backoff exponencial (máximo 3 tentativas)
  • Fallback para cache quando banco de dados estiver indisponível
  • Mensagens de erro claras sem expor detalhes técnicos sensíveis

Usabilidade e Acessibilidade

NFR-012 ALTA
Acessibilidade WCAG
A interface deve ser acessível para usuários com deficiências visuais, motoras ou cognitivas, seguindo as diretrizes WCAG 2.1.
Nível de Conformidade
WCAG 2.1 AA Padrão mínimo aceitável para aplicações corporativas
✅ Requisitos de Acessibilidade
  • Contraste mínimo de 4.5:1 para texto normal, 3:1 para texto grande
  • Navegação completa via teclado (Tab, Enter, Esc)
  • ARIA labels em todos os elementos interativos
  • Suporte a leitores de tela (NVDA, JAWS, VoiceOver)
  • Foco visível em elementos interativos (outline neon green)
  • Textos alternativos em todas as imagens
  • Formulários com labels e mensagens de erro claras
Testes de Acessibilidade
  • Análise automatizada com Axe DevTools
  • Teste manual de navegação por teclado
  • Validação com leitor de tela (NVDA no Windows)
  • Lighthouse Accessibility Score > 90
NFR-013 ALTA
Responsividade e Multi-dispositivo
A interface deve funcionar perfeitamente em diferentes tamanhos de tela e dispositivos, seguindo princípios mobile-first.
Breakpoint Resolução Layout
Mobile (S) 320px - 639px 1 coluna, menu hambúrguer, cards empilhados
Tablet (M) 640px - 1023px 2 colunas, sidebar colapsável
Desktop (L) 1024px - 1535px 3 colunas, sidebar fixa
Widescreen (XL) 1536px+ 4 colunas, layout otimizado para telas grandes
Testes de Responsividade
  • Teste em Chrome DevTools para todos os breakpoints
  • Validação em dispositivos físicos (iPhone, iPad, Android)
  • Teste de rotação de tela (portrait/landscape)
  • Touch targets mínimos de 44x44px em mobile
NFR-014 MÉDIA
Curva de Aprendizado
Novos usuários devem conseguir realizar tarefas básicas sem necessidade de treinamento extenso.
Time to First Value
< 10 minutos Desde o login até completar primeira tarefa
✅ Facilitadores de Usabilidade
  • Tour guiado para novos usuários (opcional, skippable)
  • Tooltips contextuais em campos complexos
  • Mensagens de erro claras com sugestões de correção
  • Confirmações antes de ações destrutivas
  • Undo/Redo em operações críticas
  • Atalhos de teclado documentados (Ctrl+K para busca rápida)
  • Feedback visual imediato para todas as ações

Observabilidade e Monitoramento

NFR-020 CRÍTICA
Logging e Rastreamento de Erros
Todos os erros e eventos importantes devem ser logados para permitir debugging eficiente e análise de incidentes.
✅ Estratégia de Logging
  • Sentry para tracking de exceções (frontend + backend)
  • Contexto completo: user ID, session ID, stack trace
  • Breadcrumbs de ações do usuário antes do erro
  • Alertas automáticos para erros críticos (Slack/Email)
  • Logs estruturados em JSON para fácil parsing
  • Retenção de logs: 30 dias (produção), 7 dias (staging)
Error Rate Aceitável
< 1% Percentual de requisições que resultam em erro

Métricas de Uso e Analytics
O sistema deve coletar métricas de uso para entender comportamento dos usuários e orientar decisões de produto.
Categoria Métricas Ferramenta

Features Feature Adoption Rate, Clicks Mixpanel

  • Anonimização de IPs dos usuários
  • Opt-out disponível nas configurações
  • Sem tracking de dados sensíveis (CPF, emails, senhas)
  • Conformidade com LGPD e GDPR
NFR-022 MÉDIA
Alertas e Notificações
A equipe técnica deve ser notificada automaticamente sobre eventos críticos do sistema.
✅ Sistema de Alertas
  • Downtime > 2 minutos → Slack + Email imediato
  • Error rate > 5% → Slack com severidade alta
  • API latency > 2s (p95) → Slack warning
  • CPU/Memory > 80% → Slack + PagerDuty (Fase 2)
  • Falha em backup → Email para admin
  • Tentativas de acesso suspeitas → Email de segurança

Conformidade Regulatória e Legal

NFR-023 CRÍTICA
Conformidade com LGPD (Lei Geral de Proteção de Dados)
O sistema deve estar em total conformidade com a LGPD (Lei nº 13.709/2018), garantindo os direitos dos titulares de dados.
Direitos dos Titulares (Art. 18 LGPD)
  • Acesso: Usuário pode visualizar todos os seus dados pessoais
  • Correção: Edição de dados pessoais via perfil
  • Anonimização: Dados podem ser anonimizados a pedido
  • Portabilidade: Exportação em JSON/CSV
  • Exclusão: Direito ao esquecimento (30 dias)
  • Revogação: Retirada de consentimento a qualquer momento
  • Informação: Transparência sobre uso dos dados
✅ Medidas Técnicas LGPD
  • Política de Privacidade clara e acessível
  • Termos de Uso com cláusula de proteção de dados
  • DPO designado: Thiago Nascimento Barbosa (contato@maffeng.com)
  • Registro de operações de tratamento de dados
  • Processo documentado de resposta a incidentes
  • Treinamento de equipe sobre LGPD
NFR-024 ALTA
Auditoria e Rastreabilidade
Todas as ações críticas no sistema devem ser registradas em logs de auditoria imutáveis para compliance e investigação de incidentes.
Evento Dados Registrados Retenção
Login/Logout User ID, IP, timestamp, sucesso/falha 1 ano
Criação de O.S. User ID, O.S. ID, timestamp, método Indefinido
Atribuição/Reatribuição Gerente ID, Técnico ID, motivo Indefinido
Upload de Pacote Técnico ID, O.S. ID, tamanho, checksum Indefinido
Aprovação/Rejeição Gerente ID, pacote ID, motivo, timestamp Indefinido
Exclusão de Dados Admin ID, tipo de dado, justificativa 5 anos
Alteração de Permissões Admin ID, user ID afetado, mudanças 2 anos
⚠️ Segurança dos Logs de Auditoria
  • Armazenamento em tabela separada write-only
  • Sem possibilidade de edição ou exclusão (append-only)
  • Backup independente com retenção prolongada
  • Acesso restrito apenas a admins e auditores
