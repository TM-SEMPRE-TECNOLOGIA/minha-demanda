Data Flow Diagrams

TM Gerenciador de O.S. - Fluxos de Dados Completos

Versão 1.0 | Última atualização: Novembro 2025

1. Fluxo de Importação de Excel

Como uma planilha Excel é processada e transformada em Ordens de Serviço no sistema.

1 Upload do Arquivo
Frontend: Usuário seleciona arquivo .xlsx via drag-and-drop ou file input
Validação: Tipo de arquivo, tamanho máximo (10MB)
Endpoint: POST /ordens-servico/importar
2 Parsing do Excel
Backend: Biblioteca XLSX/SheetJS processa o arquivo
Validação de Colunas: Verifica campos obrigatórios (Nº O.S., Endereço, CEP)
Normalização: Limpa dados, formata CEP, valida datas
3 Validação de Dados
Regras: CEP válido, endereço completo, nº O.S. único
Duplicatas: Verifica se O.S. já existe no banco
Erros: Array com linha e descrição do erro
4 Inserção no Banco
Transaction: INSERT em lote na tabela ordens_servico
Status Inicial: "criada"
Criado Por: ID do usuário autenticado (JWT)
5 Resposta e Feedback
Sucesso: { total: 50, importadas: 48, erros: 2, detalhes_erros: [...] }
Frontend: Modal com resultado + lista de erros
Atualização: Recarrega lista de O.S.
🔧 Stack Técnico:
Frontend: Next.js Backend: Node.js/Express Database: PostgreSQL (Supabase) Parser: SheetJS/XLSX

2. Fluxo de Upload de Fotos (Mobile → Web)

Como fotos capturadas no aplicativo mobile chegam ao banco de dados.

1 Captura no Mobile
App: Técnico captura foto via câmera
Metadados EXIF: GPS, timestamp, device info
Compressão: Reduz tamanho (max 2MB por foto)
2 Armazenamento Temporário
Local Storage: Fotos ficam no dispositivo até envio
Offline-First: Permite captura sem internet
Queue: Fila de upload quando online
3 Upload para Supabase Storage
Endpoint: POST /pacotes-levantamento (multipart/form-data)
Storage: Supabase Storage bucket "fotos-levantamento"
Path: /{os_id}/{pacote_id}/{foto_uuid}.jpg
4 Registro no Banco
Tabela: fotos_levantamento
Dados: storage_path, url_publica, metadados_exif, lat/long
Relacionamento: FK para pacotes_levantamento
5 Sincronização Completa
Status: Pacote marcado como "pendente" para validação
Notificação: Gerente recebe alerta de novo pacote
Limpeza: Fotos removidas do device após confirmação
🔧 Stack Técnico:
Mobile: React Native Storage: Supabase Storage Database: PostgreSQL (Supabase) Offline: Redux Persist

3. Fluxo de Validação de Pacotes

Como um gerente valida ou rejeita um pacote de levantamento enviado por um técnico.

1 Notificação de Novo Pacote
Trigger: Após upload completo (status = "pendente")
Notificação: Real-time via Supabase Realtime
Dashboard: Atualiza contador de "Pacotes para Validar"
2 Acesso à Fila de Validação
Endpoint: GET /pacotes-levantamento?status=pendente
Ordenação: Por data_upload (mais antigos primeiro)
RLS: Gerente vê apenas pacotes do seu contrato
3 Revisão Visual
Interface: Galeria de fotos + dados JSON
Verificação: Qualidade das fotos, dados completos
Zoom: Visualização em full-screen das fotos
4 Decisão: Aprovar ou Reprovar
Endpoint: PUT /pacotes-levantamento/{id}/validar
Payload: { status: "validado" | "rejeitado", feedback: "..." }
Update: Campos validado_por, validado_em, feedback_validacao
5 Atualização de Status da O.S.
Se Validado: O.S. status → "validada"
Se Rejeitado: O.S. status → "em_campo" (técnico refaz)
Histórico: INSERT em status_os para auditoria
🔧 Stack Técnico:
Realtime: Supabase Realtime API: REST (Express) Database: PostgreSQL + RLS Notificações: Web Push API

4. Fluxo de Notificações

Como notificações são enviadas para usuários em eventos importantes.

1 Evento Gatilho
Eventos: Nova O.S. atribuída, Pacote enviado, Validação concluída, SLA próximo
Trigger: Database Trigger ou Backend após mutation
Context: user_id, tipo_evento, metadata
2 Sistema de Notificações
Backend: Service de notificações processa evento
Filtro: Verifica preferências do usuário
Canais: In-app, Push (mobile), Email (opcional)
3 Envio para Frontend
In-App: Supabase Realtime (WebSocket)
Push: FCM (Firebase Cloud Messaging) para mobile
Email: SendGrid/Resend para notificações críticas
4 Persistência e Leitura
Tabela: notificacoes (user_id, tipo, mensagem, lida, created_at)
Badge: Contador de não lidas no header
Marcação: PUT /notificacoes/{id}/marcar-lida
🔧 Stack Técnico:
Realtime: Supabase Realtime Push: FCM Email: SendGrid/Resend Database: PostgreSQL
